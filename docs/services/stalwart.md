# Stalwart Mail

[← Services Reference](../11-services-reference.md) | [Home](../../setup.md)

---

**Purpose:** All-in-one mail server — SMTP, IMAP, and admin UI in one container.
**Port:** `8091` (admin/web) → `8080` | **Data:** `service_data/data/stalwart/`
**Other ports:** `25` (SMTP), `587` (submission), `143` (IMAP), `993` (IMAPS)

## Setup

```bash
cp stalwart/.env.example stalwart/.env
# set STALWART_PUBLIC_URL=https://mail.yourdomain.com
uv run homeserver.py dev up stalwart
```

Run the setup wizard at `http://<ip>:8091/setup` on first start.

## DNS records (required for email to work externally)

- `MX` → `mail.yourdomain.com`
- `SPF` TXT → `v=spf1 mx ~all`
- `DMARC` TXT → `v=DMARC1; p=quarantine`
- `DKIM` — generated by the Stalwart admin UI → copy the TXT record it gives you

## Notes

- Webmail clients (Snappymail, Roundcube) connect to `stalwart:143` (IMAP) and `stalwart:587` (SMTP)
- Healthcheck uses `curl -s` without `-f` — a 404 in bootstrap mode is normal, not a failure

## Port mapping under rootless Podman

Ports 25 and 143 are privileged (< 1024) — rootless Podman cannot bind them directly, so they're remapped on the host:

| Service | Host port | Container port | Privileged? |
| --- | --- | --- | --- |
| SMTP (inbound) | `8025` | `25` | yes — remapped |
| SMTP submission | `8587` | `587` | yes — remapped |
| SMTPS | `8465` | `465` | yes — remapped |
| IMAP | `8143` | `143` | yes — remapped |
| IMAPS | `8993` | `993` | yes — remapped |
| Sieve | `4190` | `4190` | no |
| Admin UI | `8091` | `8080` | no |

External clients and mail servers still connect on the standard ports — add permanent firewall forwarding rules so the OS redirects them to the remapped host ports. See [`docs/09-firewall.md`](../09-firewall.md) for the exact `firewalld`/`iptables` commands (same rules Stalwart needs, listed there once for every remapped service).
